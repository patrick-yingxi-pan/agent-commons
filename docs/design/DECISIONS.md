# Decisions log — the review surface

> The design loop runs **autonomously**: when it hits a fork, it picks the best
> production default, proceeds, and records the choice here with its rationale and the
> alternatives it rejected. **This is what you review at the end.** A decision needing
> explicit sign-off (a cost, a vendor lock-in, a security/privacy posture, an
> irreversible product call) is flagged `⚠ confirm`.
>
> One row per decision. Reference a decision from a design doc as `PD<n>`.
>
> **Id namespacing.** This tree's production decisions are **`PDn`** (the rows below).
> Bare **`Dn`** references in the design docs (e.g. `D5`, `D8`, `D11`–`D16`) point to
> the *prototype's existing* design records in
> [`docs/agent-commons.md`](../agent-commons.md),
> [`docs/shared-resource-coordination.md`](../shared-resource-coordination.md), and
> [`docs/capability-broker-architecture.md`](../capability-broker-architecture.md) — a
> separate series, not the rows here. Keeping them distinct is deliberate.
>
> **Sign-off.** All 8 decisions originally flagged for review were reviewed by the
> owner and are now `✅ confirmed` (each landed on the recommended default).

## Standing assumptions (set at kickoff)

These frame every decision below; called out so the end review can challenge the frame,
not just the leaves:

- **Target = both deployments, sequenced desktop first** (desktop sidecar first;
  hosted multi-tenant web service later), one shared contract and one product model (PD74).
- **Design, not build** — engineering-design altitude; the prototype is not converted.
- **Preserve the prototype's locked invariants** where they still apply in production
  (one door to the backend, framework-free contract, consent-gated irreversible effects,
  the model as the generation seam) unless a decision explicitly revisits one (flagged).
- **Cloud vendor-neutral by default** — name a concrete technology only as an example,
  and prefer portable abstractions; any hard dependency is flagged `⚠ confirm`.
