# Restoring a deployment that coordinates task partners

An accepted partner key can authorize work. A task journal can represent a debit, an outstanding reservation or a completed transfer. Restoring an older local record cannot undo one of those external effects. The portable restore entry point checks the current backend before writing a replacement. Ordinary workspaces with no partner records keep the existing backup procedure.

## With a readable live store

Stop all writers and keep a separate copy of the live database and its accompanying files. A restore may reuse the exact current state. If the incoming partner registry or work journal differs, the restore refuses it, including when someone has signed the older backup. Preserve the current ledger and reconcile differences with the original issuer or custodian. When just the surrounding workspace differs, a restore still needs the authorization below because account records, permissions and Project membership govern access to the ledger.

## After loss of the authoritative store

1. Isolate the site from partner workers and stop every service that can write its database. Recover the latest protected backup and independently retained issuer, site-credit and counterparty journals. Establish which operations occurred after the backup, including uncertain model charges, credit grants, award decisions and custody transfers. Reconcile every such operation against its original command and effect reference. An unresolved gap in the source records prevents a safe restore. Keep the reconciliation record outside the portable file.
2. On an independent operator machine, fingerprint the migrated snapshot using the exported `partnerRestoreDigest` function. It computes lowercase SHA-256 over UTF-8 JSON with object keys sorted recursively and array order preserved. Obtain the current live digest the same way, or use JSON `null` when recovering a lost store. The operator provisions the deployment's pinned offline Ed25519 public JWK in `TASK_PARTNER_RESTORE_PUBLIC_KEY`. An archive cannot supply its own authority.
3. Use the offline recovery key to sign a compact JWS. Its protected header contains exactly `alg=Ed25519`, `typ=partner-restore+jwt` and the pinned `kid`. Set `iss` to `deployment-operator`, `aud` to the deployment's exact canonical `TASK_PARTNER_WEB_ORIGIN`, and `iat` and `exp` to integer epoch seconds with a maximum five-minute lifetime. Include a unique `jti`, the full `snapshotDigest`, the expected `liveDigest` and a `reconciliationRef` identifying the independent review. Set `TASK_PARTNER_RESTORE_AUTHORIZATION` in the restore process environment through the operator's secret-management system. Keep the private key outside the application and backup.
4. Run the repository's managed restore against the stopped deployment. After loss of the live journal, the restore clears worker tokens and stored user selection pins, withdraws unconsumed handoffs, marks pending external commands uncertain, and retains or creates the associated recovery obligations. Active organizations enter suspension and need fresh proof of their domains. The site credit ledger retains its reconciled entries. Remove the short-lived authorization from the environment.
5. Compare the restored obligations with the independent reconciliation record before allowing new work. Resume eligible organizations through the normal operator review after fresh DNS verification. Look up uncertain effects under their original command IDs. The independent custodian recovery key and two-operator evidence procedure apply to settlement. A genuine backup and an approved restore do not establish that a specific transfer occurred.

Keep `TASK_PARTNER_WEB_ORIGIN` and the public restore trust configuration with the deployment, outside portable storage. A site with an unreadable database uses these to recognize the protected deployment even if someone presents a backup from before its first partner. A site unable to establish its last externally reconciled credit balance or custody checkpoint must recover those records before it can accept new financial work.
