# UI invariants — the ratchet ledger

> The named, machine-checkable rules every rendered surface must satisfy — the
> **oracles** behind `/ui-review` (`.claude/skills/ui-review/SKILL.md`). Each
> invariant exists because a real escape reached the user; none was invented
> speculatively. That's the ratchet: an invariant is *earned* by a bug, then
> enforced at one funnel and locked by a test that enumerates **all** its
> subjects — so the class dies, not the instance.

## Why a ledger

Code review is exhaustive because the diff *is* the enumeration and a reader is
a cheap oracle. UI review has neither by default: the artifact is rendered
behavior over **surfaces × viewports × transient states × content extremes**,
and "looks right" isn't machine-checkable as stated. This ledger is the fix for
the oracle half — it converts aesthetic judgments into named rules a sweep can
assert. The enumeration half is the repo's *shared-primitive* architecture:
because every popover / scrim / fold-header / add-trigger routes through one
primitive, a single generic test (or a `data-*` stamp) can visit all of them.
**Shared primitives are the enumeration handle that makes exhaustive review
tractable** — that's why "form follows function" (src/CLAUDE.md) is a testing
strategy, not just a styling rule.

| UI-10 | **Owner-only controls never render for a visitor, and the owner byline has one source.** A cross-tenant surface (a shared project's page, a directory card) shows a visitor only the acts the server would accept from them; ownership cues route through `bylineLabel` / `<Byline>` so "whose is this" reads identically everywhere. | UI-11 | **Every drag-operable control is keyboard-operable — and announces what it controls.** A continuous-adjustment surface (a resize divider) is a focusable `role="separator"` that axis arrow keys step (Shift = coarse), running the **same** start→move→end gesture pipeline its pointer drag runs — so clamps and persistence can't diverge between input methods — with a **distinct accessible name** per divider, the app-wide focus-visible ring as its cue, and **`aria-valuenow/-min/-max`** from the same constants the clamp enforces (REQUIRED on a focusable separator — WCAG 4.1.2: each step is announced, and "pinned at the clamp" is audible). | UI-12 | **Every displayed datum reads a LIVE source and has a SYNC path.** A surface renders a registry through its `src/api` hook (never a seed mirror — the rail's project menus once read seed-only `/projects` and a created project was nameless), and every server mutation reaches every surface that displays the mutated entity: an SSE case must invalidate a key something actually reads (reservation.changed once refreshed a key with zero consumers), a cross-tenant composed read revalidates on mount (SWR — directories, profiles, search, resolved work), and controller-owned state (the open thread) reconciles on a session push through the one narrow `onSessionPush` seam. | UI-15 | **A chooser is chrome, never a pane.** A control whose job is NAVIGATION — switching among sibling entities (a scheduled routine's run history) or choosing what a surface should show (the old empty-pane picker) — renders as a **floating click-down** over the page it serves, through the shared popover funnel (`POPOVER_SURFACE` + `useDismissable` + `usePopoverShift`), never as a persistent pane/panel splitting the layout. | UI-20 | **Text on a solid fill is legible on that fill — in every palette, both modes.** A colour that is READ (accent-as-text on the canvas, `*-strong` as emphasis copy) and a colour that is FILLED UNDER TEXT are two different jobs, and in dark mode they pull in opposite directions: the accent is *lightened* so it can be read on a dark ground, which is exactly what makes it too light to carry white. ## The ratchet procedure

When a UI escape is confirmed (by a user report or a `/ui-review` sweep):

1. **Name the invariant** the bug violated — as a rule over *all* subjects, not
   this instance ("popovers lie inside the viewport", not "widen the usage
   popup's margin").
2. **Enforce at one funnel** — a shared constant / hook / pure function in
   `src/lib/`, adopted by every subject. If subjects already share a primitive,
   the invariant lands there; if they don't, unifying them *is* the fix
   (encode invariants centrally — never patch the one place it was noticed).
3. **Lock with an enumerating test** — a source-scan that fails when a subject
   skips the funnel or re-hardcodes it (`tests/popover.test.ts` pattern), plus a
   browser assertion where rendering matters (a `data-*` stamp from the funnel
   makes subjects enumerable in the DOM).
4. **Append a row here** — statement, funnel, lock, origin. The exit criterion
   for the fix is this row existing, not the pixel being right.

Keep the list short and earned: a rule nobody's bug ever violated is checklist
bloat that dilutes the sweep.
