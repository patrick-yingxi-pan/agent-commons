# 09 · Design invariants

> **Intent.** A handful of decisions are locked in — they shape every change and must
> not silently drift. Some are *form-follows-function* rules (logically parallel
> controls share one styled primitive, so a cue can't diverge between copies) and are
> each guarded by a dedicated test; others (light-theme-only, the IPv4 bind) are
> guarded structurally by the conformance test; a couple are review-enforced
> conventions, marked as such so the absence of an automated guard is explicit rather
> than assumed. (AGENTS "Design decisions (locked in)".)

| INV-9 | **Strict core, convenient edge — an absent request field must MEAN something, or be refused.** A write path never fills an absence by *choosing for the caller*: a field is either present and concrete, or absent with a fixed, documented semantic. The allowed absence classes: **inherit** (a session's unset provider pick = its Agent's — a read-time chain to a fixed root), **complete-set value default from fixed constants** (a confirmed create-provider op's effort levels / root authority), and **none — the minimal-risk meaning** (unset budget = no cap beyond the plan; unset instructions = `''`; unset agent `tools` = the **empty** set, never the catalog — the API never *widens* a grant silently; a Project with no `defaultRole` = no preference). Never allowed: resolving an absence to a **mutable entity or a privileged value** — a registry entry, a "current default", a role picked on the caller's behalf — because the write would mean something different later and the wiring bug would surface far from its cause; that class is refused (`ValidationError` → 400). Earned instances: the agent provider/prompt bindings (MODEL-15), the commission `role` (D14 — refused when unset; the Project's optional `defaultRole` is only what pickers pre-select), and the tool grant (explicit full-catalog, stated on the consent card). An INVALID value is refused the same way, never silently normalized (the old invalid-role→writer downgrade is gone). Conveniences that spare typing — pre-selections, defaults, label→id resolution — run at the **edge**, before the request or consent card, and their result is **shown** (the picker's selection; the create-agent card names its provider + prompt and states its tool grant; the commission card names its role; the CommissionAdd picker says what a click grants). Read-side the server may decorate with **computed, viewer-relative annotations** (`isDefault`, `online`, `own`) — never stored, stripped at every mint/patch funnel. When a new request field lands, classify its absence into one of the three classes or refuse it. | `server/conflict.ts` (`ValidationError`), `server/store.ts` (`createAgentFromRequest` / `updateAgentFromRequest` / `createCommission` / `setProjectDefaultRole`, the `isDefault` strip at the mint/patch funnels), `server/model/tools.ts` (`create_agent` / `commission_agent` resolve before the card), `contract/providers.ts` (`defaultEntry`), `contract/cowork.ts` (`Project.defaultRole`) | instance locks: `tests/registry-defaults.test.ts`, `tests/routes-worker-agents.test.ts`, `tests/commission.test.ts`, `tests/model-tools.test.ts`, `tests/consent-state.test.ts`; the general classification of each NEW field is review-enforced (no automated guard for fields not yet written) | ✅ |
