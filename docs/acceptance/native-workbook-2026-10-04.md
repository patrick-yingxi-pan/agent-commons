## Observed workflow

The generated workbook contained four worksheets: `Overview`, hidden `Hidden`,
`Selected values`, and `Recalculate first`. Only the three visible worksheets
were offered. The hidden-sheet count and source range were disclosed.

1. Cancelling the actual Open dialog retained the empty Sheet draft, blank name
   and disabled Create action.
2. Selecting the workbook opened read-only review, defaulting to `Overview`.
   Neither selection nor review populated the editable draft.
3. Choosing `Recalculate first`, whose formula had no stored result, showed
   recalculation/save guidance and disabled **Use imported sheet**.
4. Choosing `Selected values` showed the exact literal Unicode text, leading-zero
   identifier and saved formula result. Unchecking first-row headers retained
   both source rows under generated Column A–C headers; rechecking restored the
   authored headers. The unselected and hidden bodies were not adopted.
5. **Use imported sheet** populated the editable fields and suggested the source
   name. Read-only API checks still returned an empty registry and content map.
   Only **Create sheet** saved one artifact at its canonical exact-ID page.
6. **Edit sheet** preserved the imported values; a distinguishable note was added
   and saved. Download was disabled while editing and enabled after acknowledgement.
7. **Download XLSX** opened an actual Save dialog. A separate export filename in
   the generated fixture directory preserved the input workbook. The downloaded
   bytes exactly matched the authorized revision-one export; ZIP CRC checks passed.
8. After native-menu Quit completed, only the generated source workbook was moved
   to a holding subdirectory. Its original path was proven absent before relaunch.
   The artifact reopened from the ordinary sidebar and showed its exact saved
   values and note. Registry, body, aliases and current export matched the
   pre-restart state. The relaunched app was then quit normally.
